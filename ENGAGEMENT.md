# Anonymous engagement signals

ArcadeRTFM already has Cloudflare Web Analytics enabled for the domain. It counts
browser visits and performance separately from raw HTTP request traffic.

This small, first-party addition counts **actions** rather than HTTP page fetches:

| Signal path | Counted when |
| --- | --- |
| `/signals/search-results.txt` | A user stops typing a search that returned matches |
| `/signals/search-empty.txt` | A user stops typing a search with no matching results |
| `/signals/machine-open.txt` | A user opens a machine's details on the homepage |
| `/signals/manual-open.txt` | A user clicks a manual link on the homepage or machine page |

These are static text files generated by `build.mjs`. The JavaScript makes
a same-origin, credential-free GET for each event. No endpoint, database, new
service, API key, or third-party tracker is required.

## Privacy

The signals contain **no search terms, filenames, page URLs, referrers, cookies,
visitor IDs, session IDs, machine IDs, or device fingerprints**. They are not
suitable for following an individual person between pages. The client honours
Global Privacy Control and Do Not Track and never sends a signal for a
programmatically generated `click` or `input` event.

Cloudflare still processes ordinary connection metadata (including IP address
and user agent) in its standard edge traffic handling, as it does for every
request to the archive. This is *anonymous action counting*, not a claim that
the CDN sees no request metadata.

## Reading the results

Use the existing Cloudflare HTTP Analytics dataset for the
`arcadertfm.com` zone. In Cloudflare Analytics SQL, run:

```sql
SELECT clientRequestPath, COUNT(*) AS actions
FROM events.httpRequests
WHERE clientRequestPath LIKE '/signals/%'
  AND zoneTag = '<ARCADERTFM_ZONE_TAG>'
  AND timestamp >= NOW() - INTERVAL '7' DAY
GROUP BY clientRequestPath
ORDER BY actions DESC
```

Replace the placeholder with the actual zone tag, or supply zone scope and
time range separately in the query API. This dataset uses adaptive sampling:
reported counts may be estimates, especially at high volume. Signal paths
are only emitted by the browser on an actual interaction, but browser
automation can still simulate genuine clicks. They are **not** verified
unique human visitor counts.

Cloudflare's separate Web Analytics dashboard remains the place to inspect
browser-based page views, engagement and traffic sources.

## Validation

1. Run `node build.mjs` and confirm all four `dist/signals/*.txt` files
   exist and each generated machine page includes `/engagement.js`.
2. Open the built site in a browser and search for a game, expand its details,
   and click a manual link.
3. Browser Network should show GET requests to matching signal paths.
   The requests should have no cookies or referrer and return HTTP 200.
4. Wait for Cloudflare analytics to aggregate the traffic before querying.

There is no extra service to switch off: removing the script references and
the generated signal files stops these action counts. Web Analytics continues
to function independently.
